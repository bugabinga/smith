# ADW MJS Control Plane Design

## Decision

ADW becomes a dependency-free Node.js control plane under `adw/`. GitHub Actions provides triggers, isolated jobs, credentials, and CI artifact transport only. All ADW policy, provider invocation, artifact validation, fallback, reconciliation, and forge mutation lives in MJS.

PROJECT-INVARIANTS §1 explicitly exempts this control plane. Product build, test, documentation, gate, and release-artifact construction remain Cargo/xtask-only. ADW has no package manifest, lockfile, npm library dependency, or product code.

GitHub is the first forge adapter, implemented through the `gh` and `git` CLIs. Issues, comments, pull requests, labels, checks, branches, releases, milestones, and repository settings are forge capabilities. No ADW database exists; forge state and Git history are authoritative.

Claude and Codex run through their CLIs. `claude-code-action` is removed. `CLAUDE_CODE_OAUTH_TOKEN` works with `claude -p` when generated by `claude setup-token`; `--bare` is forbidden because it ignores subscription OAuth.

## Goals

- Delete workflow-embedded shell, jq, prompts, provider setup, routing, and reducers.
- Replace 22 ADW workflows with thin permission-scoped wrappers.
- Isolate every GitHub field, endpoint, and CLI call behind one adapter.
- Give both providers one assessment contract without sharing credentials.
- Keep forge write credentials and patched code out of provider jobs.
- Make every policy transition executable under `node --test`.
- Support offline fixtures, local read-only dry-runs, and disposable-forge live tests.

## Non-goals

- A daemon, queue, database, service, package manager, or npm runtime dependency.
- A generic plugin framework.
- A second production forge adapter before one is needed.
- Emulating a capability absent from a future forge.
- GitHub Projects v2; canonical ADW planning uses issues, milestones, parent/sub-issues, labels, and Git history, so stale board/card instructions are deleted at cutover.
- Changing Smith product behavior or `docs/SPEC.md`.

## Baseline

The current ADW has 22 workflows and 2,892 YAML lines, 118 scattered `gh` calls, 27 provider invocations, 14 duplicated Codex setup blocks, and 495 shell-test lines. Four workflows contain half the YAML. A normal PR can cause roughly 35 workflow runs through label and workflow-run cascades.

## Modules and dependency direction

```text
adw/
  main.mjs
  core.mjs
  roles.mjs
  providers.mjs
  github.mjs
  vcs.mjs
  schemas/
  test/
    fixtures/
```

`core.mjs` imports nothing from the other production modules. `roles.mjs` is data plus pure validators. `providers.mjs`, `github.mjs`, and `vcs.mjs` are leaf adapters. `main.mjs` composes them. Splitting a module requires one responsibility that can be tested without its caller; arbitrary file-count ceilings are forbidden.

### `main.mjs`

The only executable entrypoint. Commands:

- `prepare`: normalize the CI event and read bounded forge state into a snapshot.
- `assess --provider claude|codex`: invoke exactly one provider with one credential.
- `reduce`: combine provider envelopes according to `single`, `quorum`, or `advisory` role mode.
- `verify`: structurally apply and attest a patch, or attest a state-only decision, without executing target code.
- `apply`: re-read live state, validate the reduced decision, and execute permitted operations without running patched code.
- `reconcile`: derive missing work and repair partial transitions from live forge state.
- `audit`: read settings/rulesets and report drift without changing owner-controlled policy.
- `dry-run`: perform normal reads and print stable mutation intents without writes.

Exit codes: `0` artifact/no-op complete, `2` unsupported/invalid input, `3` stale state, `4` provider unavailable, `5` forge failure, `6` artifact-contract failure, `7` verification failure.

### `core.mjs`

Pure functions define normalized records, revision fingerprints, event dispatch, artifact qualification, hold rules, provider reduction, review conflict reduction, route transitions, merge eligibility, idempotency keys, operation preconditions, and reconciliation plans. It imports no process, filesystem, forge, provider, or VCS APIs.

### `roles.mjs`

Each role names:

- semantic charter path;
- mode: `single`, `quorum`, or `advisory`;
- preferred/fallback or quorum providers, model, effort, and timeout;
- required forge capabilities;
- snapshot fields and maximum sizes;
- provider payload schema;
- artifact validator and explicit no-op shape;
- allowed operation types and protected paths;
- patch limits when code changes are allowed.

Charters remain canonical under `.claude/agents/` and `.claude/skills/`. Assessment-only charter wording lands in the atomic cutover, never while legacy providers remain authoritative. Before cutover, shadow probes append a tokenless structured-output boundary without changing canonical charters. After cutover, charters tell providers what decision or patch to produce; only reducers mutate the forge.

### `providers.mjs`

One shell-free process runner uses `spawn` with `shell: false`, an explicit environment allowlist, temporary homes, bounded output, and `AbortSignal.timeout`.

Claude:

- exact pinned `@anthropic-ai/claude-code` version installed under a temporary prefix by MJS;
- `claude -p` with `CLAUDE_CODE_OAUTH_TOKEN` and `--json-schema`;
- no `--bare`, Anthropic API key, bearer override, forge token, SSH agent, or inherited home.

Codex:

- exact pinned `@openai/codex` version installed under a temporary prefix by MJS;
- `codex exec` with `--output-schema` and `--output-last-message`;
- `CODEX_AUTH_JSON` mode `0600` under a temporary Codex home, removed in `finally`;
- no forge token or cross-provider credential.

Pinned package versions and expected CLI `--version` strings live in `roles.mjs`. There is no package manifest. Installation/version failure is provider unavailability.

A provider emits only its role payload. The runner stamps the trusted envelope: schema version, role, provider, model, idempotency key, trusted control-plane SHA, snapshot digest, CLI version, run/job/attempt identity, payload digest, and timestamps.

### `github.mjs`

The only production file containing `gh`, `GH_TOKEN`, GitHub event fields, endpoints, author identities, or pagination. It invokes `gh` with `shell: false`, JSON stdin for mutations, explicit pagination, bounded output, and typed failures.

The base forge port covers:

- issues, comments, pull requests, labels, checks, and branches;
- milestone create/update/close and parent/sub-issue relationships;
- merge arming and merge-method capabilities;
- issue/PR timelines for actor-qualified owner decisions;
- workflow/check runs, reruns, and dispatch;
- label definitions, repository settings/rulesets read-only, security alerts/analyses, releases, and tags.

`capabilities()` advertises support. Roles fail explicitly when a required capability is absent. Common records use opaque IDs, ISO timestamps, forge-neutral actor/repository identities, and resource revisions. GitHub-only fields never escape normalized adapter output.

### `vcs.mjs`

The only production file invoking `git`. It creates clean worktrees, computes/apply patches, validates paths/modes, disables hooks, commits, and pushes. Provider and verification jobs have no credentials. Apply may push with the short-lived forge credential but executes no patched files, hooks, build scripts, or tests.

## Resource revisions

Staleness is resource-specific, not universally a Git SHA:

- pull request/review/build: head SHA plus base repository/ref;
- issue/comment: entity `updatedAt` plus canonical label/comment-marker digest;
- schedule/backlog: default-branch SHA plus bounded collection digest;
- alert/settings/ruleset: entity ID plus updated timestamp or canonical digest;
- tag/release: tag target SHA plus release/asset digest.

Snapshots list each revision and the operations that depend on it. Apply re-reads only those resources and returns stale-state without mutation when a precondition changed.

## CI trust boundary and transport

Provider execution, patch verification, target execution, and forge writes run on separate fresh runners.

1. **Prepare:** trusted control-plane checkout, short-lived App token, bounded snapshot and routing metadata.
2. **Primary assessment:** one conditional Claude or Codex job receives only its own credential. Quorum routes run both primary jobs independently.
3. **Fallback assessment:** two conditional jobs encode the inverse dependency: Codex fallback depends on Claude-primary failure, while Claude fallback depends on Codex-primary failure. Routing comes from the snapshot; valid artifacts skip fallback.
4. **Reduce:** no secrets; combines stamped envelopes and emits a decision.
5. **Verify:** no secrets; validates state-only decisions or structurally applies exact patch bytes in a clean target checkout and computes the resulting tree, but executes no target code.
6. **Apply:** fresh trusted control-plane checkout and operation-scoped App token; rechecks state, reapplies the exact verified bytes, performs no patched execution, then mutates forge/VCS.
7. **Product CI:** after a patch is pushed, the existing required `check` workflow runs Cargo/xtask on the resulting PR head without ADW/provider credentials. Merge eligibility requires its current-head success.

Every checkout uses `persist-credentials: false`. Control-plane code comes from `main` for issue/schedule/tag events and the trusted PR base SHA for pull-request events. Target code lives in a separate directory and never controls the MJS executable.

CI artifacts have fixed names and files:

- `adw-snapshot/snapshot.json`;
- `adw-assessment-claude/envelope.json` and optional `change.patch`;
- `adw-assessment-codex/envelope.json` and optional `change.patch`;
- `adw-decision/decision.json` and optional `change.patch`;
- `adw-verification/verification.json` and, only for patch decisions, exact `change.patch`.

Every JSON document has a schema version, trusted control-plane SHA, maximum 256 KiB, and a sibling `.sha256` file containing the digest of its exact bytes. Input digests live in downstream JSON; no document contains its own digest. Every downstream job checks out that exact trusted SHA and apply also requires it to remain the live default/base control revision. Verification records `kind: state` with the decision/precondition digests or `kind: patch` with those digests plus resulting tree. Patches have a 1 MiB/100-file default ceiling, UTF-8 unified-diff format, base SHA, sibling SHA-256 file, and resulting-tree digest.

Patches reject absolute/parent paths, `.git`, `.gitmodules`, symlinks, submodules, devices, binaries, mode changes outside regular executable bit, omitted/truncated files, and conflicting renames. Providers may never patch `docs/SPEC.md`, `docs/PROJECT-INVARIANTS.md`, `.github/CODEOWNERS`, `.github/rulesets/**`, `.claude/settings.json`, `adw/**`, or the thin ADW wrappers; these are the control plane that judges them. Other protected ADW/config paths require a triaged ADW role and owner-reviewed PR. `adw-doctor` reports control-plane fixes as owner issues rather than self-modifying PRs; this deliberate restriction replaces its unsafe legacy option while preserving diagnosis. Role-specific limits may be lower, never higher without owner approval.

Downstream jobs use `if: always()` where needed so provider failure still reaches reduce/apply to publish a red terminal check. Missing or malformed transport artifacts fail closed.

## Workflow wrappers

Target operational wrappers:

1. `adw-issues.yml`: issue, issue-comment, and backlog events.
2. `adw-pulls.yml`: pull request, review, review-comment, and check events.
3. `adw-maintenance.yml`: default-branch pushes, schedules, alerts, reconciliation, spec-change planning, settings/labels audit, and manual dispatch.

`adw-selftest.yml` remains CI, not an operational ADW wrapper. The premature `adw-release.yml` is deleted: PROJECT-INVARIANTS §8a and issues #104/#120/#122 keep release automation absent until `xtask release` and required cross-build proofs exist.

Wrappers may contain triggers, one shared writer concurrency key, explicit job permissions, trusted/target checkouts, App-token minting, artifact upload/download, provider secrets, routing-based provider job conditions, and one `node adw/main.mjs ...` command per ADW job. They contain no prompts, `gh`, jq, provider commands, policy shell, mutation logic, target execution, or implicit App permissions.

The exact `merge-gate` and `check` contexts remain stable. `adw-pulls.yml` publishes `merge-gate` for the current head and arms squash auto-merge only after all required evidence. `risk:high` clears only after an owner-associated timeline event recorded in an App marker.

## App identity and permissions

App login and installation identity are workflow inputs/config, never discovered through `/user`. Each prepare/apply job mints a token with explicit permission inputs derived from a documented matrix. Omitted token permissions fail wrapper tests.

Minimum classes:

- issue-state apply: contents/issues/pulls read, issues write;
- issue-code apply: contents, pull requests, and issues write;
- pull-state apply: contents, issues, pull requests, and checks write, including the contents permission required to arm auto-merge;
- pull-code apply: contents, pull requests, and issues write;
- maintenance read: contents/issues/pulls/actions/security-events/Dependabot-alerts/administration read;
- maintenance state apply: issues/pulls/actions write only for the selected operation; administration and security capabilities remain read-only.

Provider and verify processes receive no App token, GitHub token, persisted checkout credential, git push credential, SSH agent, or secret from the opposite provider.

## Events and snapshots

`prepare` reads `GITHUB_EVENT_PATH` only through the forge adapter and normalizes supported events into repository, actor, entity, action, resource revisions, and timestamp.

Snapshots mark trusted project instructions separately from untrusted issue/PR/comment/diff data. Required truncation or oversized input fails closed. Automatic provider instruction discovery is disabled where possible; provider cwd contains the trusted control-plane checkout and the untrusted target is passed as data/path under explicit prompt boundaries.

## Assessment, reduction, and operations

Payload outcomes are positive artifact, valid negative artifact, explicit no-op, or unable. Providers never emit arbitrary forge/VCS commands.

`reduce` accepts a closed operation set:

- comments and targeted labels;
- issue create/update/close, milestone create/update/close/assignment, parent/sub-issue link;
- branch/PR create or update;
- check publication, workflow/check rerun, and squash-merge arming;
- workflow dispatch and label-definition sync;
- settings/ruleset drift issue or comment, never settings/ruleset mutation;
- no-op or terminal failure.

Equivalent existing artifacts are idempotent success. Conflicting duplicates fail. Non-idempotent creates carry deterministic markers in title/body/check external IDs and are searched before mutation. Route transitions retain legacy `smith:claude-attempt/v1` and `smith:builder-route/v1` parsing until all in-flight work is terminal.

A high-risk security decision writes `risk:high` plus `smith:risk/v1` containing head SHA, finding digest, and open state. Only an owner-authored later label-removal timeline event for that same head closes the marker; non-owner removal is reverted, and a new head requires fresh security assessment. A clean current-head assessment may close only findings its schema explicitly addresses.

Merged PRs carry deterministic downstream obligations derived from changed paths, including linked-work finalization and docs assessment. Each completed obligation writes `smith:merge-finalized/v1` with PR, merge SHA, role, and artifact digest. Reconciliation scans bounded merged PR history for missing obligations and replays them idempotently; provider failure creates a terminal check/owner issue and leaves the obligation retryable without changing merged code.

Role idempotency keys are semantic: issue+route+source revision, PR+head+review kind, milestone+spec digest, or alert identity+state. Every mutating apply and reconciliation job uses the same repository-wide `adw-write` concurrency group with `cancel-in-progress: false`. Assessment jobs may run concurrently. GitHub may retain only one pending writer; scheduled reconciliation repairs any dropped event.

GitHub lacks general compare-and-swap for labels/comments. Correctness therefore combines global writer serialization, pre-write live revision checks, targeted mutations, deterministic markers, and retry-safe equivalent-artifact detection. It never replaces full label sets.

## Provider modes and fallback

- `single`: preferred assessment; fallback job invokes only after provider-unavailable, timeout, malformed output, or missing required artifact. Role policy may forbid fallback authority for protected paths, forks, incomplete/oversized diffs, or unsupported representations; these remain red for owner review.
- `quorum`: both isolated provider jobs run; reducer combines them. Correctness rejection and security high risk win conflicts.
- `advisory`: optional result cannot satisfy a required gate.

Valid positive, negative, and explicit no-op payloads are artifacts, not provider failure. Both-provider failure publishes a sanitized red terminal result. Codex quota preflight is omitted initially; invocation errors already drive fallback. Claude subscription quota has no supported programmatic endpoint.

## Dry-run and tests

Offline tests require no secrets. Fixture mode injects an in-memory forge, VCS, and providers. Live `dry-run` may use local `gh` for reads but records every mutation intent without writes or provider invocation unless explicitly requested.

All tests use `node:test` and `assert/strict`:

- event normalization for every supported action and malformed/missing revision;
- Claude-primary, Codex-primary, valid-primary skip, inverse fallback dependencies, quorum, success, negative, no-op, timeout, spawn error, auth/429, malformed/oversized output, and both-fail;
- every role artifact and operation contract, including pioneer result variants;
- adapter pagination, 404/auth/server distinction, scan bounds, exact argv/stdin, actor identity, and capability failure;
- state-only and patch verification, control-SHA drift, traversal, binary, symlink, submodule, protected-path, size/file limits, digest mismatch, resulting tree, and proof that verify/apply never execute target code;
- issue-to-merge scenarios for both builders, revisions, review disagreement, security rejection, sticky-risk owner clearance, holds before each write, partial retries, missed events, docs/dependency/alert/settings flows, and post-merge failure recovery;
- legacy marker import and current-head review evidence regressions;
- wrapper triggers, shared concurrency, trusted refs, `persist-credentials: false`, explicit permissions, isolated secrets, artifact boundaries, exact required check names, and absence of embedded policy/tools.

Production live tests are read-only dry-runs and tokenless provider schema probes. All writes, forced provider failures, partial retries, auto-merge, signing verification, and cleanup run in a disposable repository with a separately scoped App.

## Migration and authority handoff

### Phase 1: foundation

Land modules, schemas, fixtures, and self-tests. Run read-only shadow `dry-run`; legacy remains the only writer.

### Phase 2: parity

Replay captured production event fixtures and compare MJS intents against legacy outcomes. Run the disposable-repository matrix and tokenless provider schema probes with an appended assessment boundary. Canonical charters remain untouched while legacy can run. No production writes.

### Phase 3: atomic cutover

One protected PR adds the three wrappers, converts semantic charters to assessment-only language, and deletes all superseded operational workflows/shell reducers, including the premature release workflow. Immediately before merge, the owner disables every legacy ADW workflow through the forge, cancels/drains all active runs, and verifies none can start. The owner then merges the cutover; newly added wrapper files become enabled and their apply jobs share `adw-write`.

MJS imports existing route/review/jam markers, branches, open PRs, labels, milestones, and armed auto-merges. Rollback is the invariant-permitted owner direct-push touchpoint: disable all three wrappers, drain their runs, create and sign a revert locally, push it directly to `main` through the owner RepositoryRole bypass already encoded in the ruleset, then re-enable restored legacy workflows. Irreversible forge operations are never claimed reversible; rollback prevents new writes and reconciliation repairs compatible state.

### Phase 4: soak and deletion

Observe one natural event of each latency-critical kind and two scheduled cycles. Remove legacy marker compatibility only after no active legacy record remains. Update `AGENTIC-DEVELOPMENT.md`, close superseded ADW issues, and retain only fixture-based regression evidence.

## Completion criteria

- Three operational wrappers plus self-test; operational YAML below 400 lines.
- No `claude-code-action`, workflow/shell `gh`, jq, provider setup, inline prompt, or policy reducer.
- No provider process receives forge credentials.
- Every invariant-permitted ADW role and forge capability has an executable artifact contract; release-manager remains deferred with release automation.
- `node --test adw/test/*.test.mjs`, existing Cargo checks, wrapper contracts, dry-run parity, and disposable-repository matrix pass.
- Live `merge-gate` and `check` remain required; auto-merge remains enabled and squash-only.
- Every commit on `main` remains GitHub-verified; branch signatures are optional, matching the enforced invariant and current Codex behavior.

## Residual risks

- Forge semantics differ; unsupported capabilities fail explicitly.
- GitHub has no universal mutation CAS; concurrency plus preconditions and idempotent markers bound the residual.
- Provider CLIs can modify assessment worktrees; fresh tokenless verification and token-bearing no-execution apply contain that trust.
- Exact npm CLI installation is still supply-chain input; pinning/version checks match or improve current behavior but do not vendor providers.
- GitHub Actions remains initial CI transport; replacing it changes wrappers and `github.mjs`, not reducers or role policy.
